## 4. Недочёты M0, которые исправить перед сетевыми испытаниями

### QA-раннер: изменение файлов раньше проверки порта

`scripts/godot/qa_server.py` сначала выполняет `--reset`/копирование fixture, затем вызывает `is_port_in_use`. При занятом порте возможно уже удалить или заменить состояние существующей QA-партии, хотя второй сервер не запустится.

Проверено через импорт модуля с подменой `QA_DIR` на специально созданный `mock-qa` в папке аудита и `is_port_in_use -> True`: созданный тестовый `snapshot.json` удалился, затем произошёл выход с кодом 1. Реальные QA-файлы и пользовательские сейвы в этом опыте не использовались.

Нужно: проверить порт, валидность параметров/fixture и разрешённые пути **до** изменения файлов. Не удалять сейвы при неуспешном preflight. Не использовать один QA-каталог одновременно для разных серверов.

### QA-раннер: потеря кода ошибки дочернего процесса

Результат `proc.wait()` игнорируется. Сбой сервера может закончиться нормальным завершением Python-скрипта и ложным успехом внешней проверки.

Подтверждено подставным `Popen`, чей `wait()` возвращает 7: `start_server()` вернулся нормально (`None`). Настоящий сервер не запускался.

Нужно: возвращать код дочернего процесса из скрипта; явно обрабатывать ошибку запуска. На Windows проверить завершение всего **своего** дерева `npx/tsx/node`, чтобы остановка раннера не оставляла сервер на порту. Не завершать посторонние процессы по одному имени `node.exe`.
