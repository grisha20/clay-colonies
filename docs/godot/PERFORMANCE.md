# Отчёт о производительности и нагрузочные цели

- **GPU**: NVIDIA GeForce RTX 4070 (12 ГБ GDDR6X VRAM)

- **RAM**: 32 ГБ DDR4-3600

## 3. Стратегии оптимизации

1. **MultiMeshInstance3D** для одинаковых статичных объектов ландшафта (трава, мелкие камни, секции забора).
2. **Общие материалы**: единый PBR шейдер терракоты с параметром оттенка для племён A/B, исключающий смену шейдерных программ.
3. **Ограничение динамических источников света**: тени рассчитываются только от солнца и костров; у жителей нет индивидуальных точечных источников света.
4. **Следы ног**: эффективный пул декалей / GPU-частиц с постепенным затуханием альфа-канала.

## Диагностический замер после замечаний владельца — 20.10.2026

Godot 4.7.2, Forward+ Vulkan / RTX 4070, окно **1280×720**, production WorldObserver, отдельная свежая QA-партия, 18 жителей. После 3 с прогрева — 12 с измерения реального времени между process_frame через Time.get_ticks_usec(), без MovieMaker и без параллельных тестов. Это короткая диагностика, не нагрузочная приёмка M5 и не сравнение одинаковых детерминированных миров.

| Прогон | Средний FPS | Кадр p50 / p95 / max, мс | Доставка snapshot p50 / p95 / max, мс |
|---|---:|---|---|
| До исправления темпа | 97.13 | 9.994 / 12.280 / 56.285 | 109.740 / 118.556 / 135.542 |
| После исправления темпа | 98.06 | 9.977 / 11.761 / 57.274 | 109.891 / 116.134 / 133.343 |

Эта правка не является оптимизацией FPS: она устраняет воспроизведённые остановки курсора при устойчивой доставке чуть медленнее 100 мс. Длинные кадры остаются. Позиционные различия между последовательными кадрами включают коррекции на snapshot и не годятся сами по себе для оценки скорости обычного шага. Требуется отдельная классификация таких коррекций; плавность всего живого мира пока не подтверждена. Сырые локальные результаты: `tmp/qa/motion-profile-ff7558d9/profile.json` и `tmp/qa/motion-profile-fixed-4d67c085/profile.json` (ignored, не поставочные артефакты). Цель 1080p/100 жителей и стресс-строки выше остаются непроверенными.

## Подлагивания в поздней партии — 21.10.2026

Жалоба владельца: время от времени игра подлагивает, ПК гудит громче. Замер на изолированном QA-сервере с миром поздней партии (94 жителя, 58 построек, `tmp/qa/fixtures/late_match.json`) пробником `godot/tests/visual/probe_hitches.gd`. Он пишет каждый кадр дольше 25 мс с разбивкой по участкам (`godot/scripts/game/frame_perf.gd`) и сводку.

**Причины.**
- Клиент. Каждый снимок, 10 раз в секунду, давал кадр около 30 мс. На жителей уходило 15–20 мс: каждая проверка пути заново считала глубокий хеш всего массива построек и перебирала все здания. Ещё 4–5 мс занимал разбор JSON, плюс раз в секунду приходили лишние 200 КБ феромонов, которые Godot не рисует. Редко, но один обход препятствия занимал до 371 мс: перебирались обходы вокруг каждого сегмента стены на карте.
- Сервер. Шаг рос до 15–25 мс, отдельные шаги длились до 600 мс. Каждая проверка отрезка перебирала все постройки и заново собирала список заборов. Каждый житель на каждом шаге склеивал строку id всех построек. Готовое здание сбрасывало маршруты всем жителям сразу. A* к недостижимой цели обходил всю карту.

**Что сделано.**
- Клиент: индекс препятствий узнаётся по самому массиву, без хеша; здания разложены по клеткам 8×8; стоящим жителям маршрут не считается; обходы ограничены бюджетом 3 мс на снимок, A* — 600 шагами; JSON разбирается в фоновом потоке, применяется только свежий снимок; клиент просит сервер не слать феромоны (`setView … pheromones: false`).
- Сервер (`shared/surfaceNavigation.ts`): индекс препятствий с числовой подписью достроенных зданий, пересчёт только при изменении длины массива или явной отметке `markObstaclesChanged()` при завершении стройки; кеш «клетка заблокирована рельефом»; A* сдаётся после 6000 клеток; маршрут сбрасывается, только если новое здание его действительно перекрыло; ключ регионов `taskAccess` стал числовым; `scoutTrail` больше не уходит в сеть.
- Точность: `npm run check:navparity` сравнивает индексированную навигацию со старой полной (`server/src/bench/reference/`) — 49 тыс. ответов совпали; 14 из ~650 случайных дальних маршрутов теперь останавливаются по лимиту A*.

**Результат.**

| | было | стало |
|---|---|---|
| 1×, рывков >25 мс за 40 с | ~360 (каждый снимок) | 8 (почти все в момент подключения) |
| 5×, p99 кадра | 63 мс | 19 мс |
| сервер, шаг на этом мире (повтор `spikeBench`) | p50 10,8 / p95 44 / max 650 мс | p50 3,3 / p95 7 / max ~180 мс |
| сервер в живой игре на 5× | 22 мс на шаг (ядро загружено полностью) | 2,5–6,5 мс |
| снимок | 160 КБ + 360 КБ раз в секунду | 129 КБ |

Кадры ровно по 50 мс в пробнике — это не рывки, а лимит 20 FPS, когда окно игры не в фокусе (сделан раньше, чтобы фоновая игра не грела ПК).
