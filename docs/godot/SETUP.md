# Инструкция по настройке и запуску Godot-клиента Clayfolk

## 1. Зафиксированное окружение

- **ОС**: Windows 11 Pro x64
- **ЦП**: AMD Ryzen 5 5600X (6 ядер, 12 потоков)
- **ОЗУ**: 32 ГБ
- **ГП**: NVIDIA GeForce RTX 4070 (12 ГБ VRAM, драйвер 572.x)
- **Godot Engine**: `4.7.2.stable.official.ed1daf0bf` (`godot_console` / `godot`)
- **Godot Renderer**: `Forward+` (Vulkan)
- **Blender**: `4.2.3 LTS` (`blender`)
- **Node.js**: `v24.17.0`, `npm 11.13.0`
- **Python**: `3.11.6` (запуск через `py`)
- **FFmpeg**: `C:\ffmpeg\bin\ffmpeg.exe`

## 2. Структура проекта

```text
godot/                  # Проект Godot 4 (project.godot, scenes, scripts, assets)
art/blender/            # Исходные модели Blender (.blend) и скрипты генерации/экспорта
scripts/godot/          # Скрипты изолированного QA-сервера, тестов и экспорта

tmp/qa/                 # Изолированная директория состояния QA-сервера (в .gitignore)
```

## 3. Запуск изолированного QA-сервера

Чтобы не повредить основную партию игрока (`snapshot.json`) и файлы обучения (`genome*.json`, `spider_genome.json`), QA-сервер запускается на выделенном порту `8788` с изолированным хранилищем:

```powershell
# Запуск чистого QA-сервера на порту 8788
py scripts/godot/qa_server.py --port 8788 --reset

# Запуск с существующим QA-сохранением
py scripts/godot/qa_server.py --port 8788
```

## 4. Запуск Godot-клиента

### Двойным кликом

В корне проекта открыть **`Запуск Godot.bat`**. Он запускает текущие исходники Godot из `godot/` и показывает стартовое меню: «Продолжить», «Новая игра — случайная карта», «Новая игра — классическая карта», «Загрузить сохранение». Чтобы увидеть новую генерацию мира вместо старой карты, выбрать новую случайную игру; перед заменой текущая партия сохраняется в слот.

Запускатель подключает меню к отдельному QA-серверу на 8788, хранит партию и слоты в `tmp/qa/play-random/` и останавливает сервер после закрытия игры. Первый запуск создаёт случайный мир с озёрами, холмами и горами; следующие продолжают его. Прежняя плоская тестовая карта остаётся нетронутой в `tmp/qa/play/`, её слоты также сохранены там. Основные сохранения проекта не используются. При занятом порте запуск отменяется; чужие процессы не останавливаются. Требуются Godot и Python (`py`) в PATH и установленные npm-зависимости. Журнал сервера: `tmp/qa/play-random/launcher-server.log`. После обновления исходников уже открытое окно игры нужно закрыть и запустить заново.

Существующий **`Запуск.bat`** запускает браузерную 2D-версию.

### Режим разработки (Godot Editor)

1. Открыть Godot Engine: `godot -e --path godot`
2. Открыть проект в папке `godot/`
3. F5 открывает стартовое меню и подключается к серверу на 8787, который должен быть запущен отдельно. Для изолированного запуска сервера вместе с игрой использовать `Запуск Godot.bat`. Лаборатория остаётся отдельной сценой `scenes/lab/resident_lab.tscn` (F6).

### Запуск из командной строки

```powershell
# Сетевой клиент к уже запущенному собственному QA-серверу
godot_console --path godot -- --qa-port 8788

# Интерактивный запуск визуальной лаборатории персонажа (M1.1)
godot --path godot scenes/lab/resident_lab.tscn

# Автоматический визуальный тур со сменой ракурсов и скоростей (41 сек)
godot --path godot scenes/lab/resident_lab.tscn --tour

# Автоматический приёмочный тест опоры стоп (Normal PASS + Negative Test FAIL)
godot_console --headless --path godot scenes/lab/resident_lab.tscn --test-grounding

# Запуск набора тестов безопасности QA-сервера
py scripts/godot/test_qa_server.py
```

### Стартовое меню, случайный мир и сохранения

Обычный запуск (F5 или `godot --path godot`) открывает меню поверх живого мира и подключается к `ws://127.0.0.1:8787`: «Продолжить», «Новая игра — случайная карта», «Новая игра — классическая карта» (два прежних озера), «Загрузить сохранение». Новая игра сначала сохраняет текущую партию в слот «Перед новой игрой». На верхней панели — «Сохранить» и «Меню». Слоты лежат в `saves/` рядом с `snapshot.json`; QA-сервер хранит их в своём каталоге состояния.

Меню против изолированного сервера: `godot --path godot -- --menu-address ws://127.0.0.1:8793`. С `--qa-port`/`--connect` меню не показывается (автоподключение для тестов и записей). Проверка: `godot --path godot --script res://tests/integration/test_start_menu.gd -- --server-port 8793`.

Сервер: команда `newGame { seed?, classic? }`, `saveGame { name? }`, `loadGame { id }`. Первая партия без сохранения тоже создаётся на случайной карте.

### Камера и выбор в сетевом клиенте

WASD/стрелки перемещают камеру, колесо плавно меняет масштаб. «Лагерь A/B» берёт позиции из текущего snapshot. ЛКМ выбирает жителя и показывает его роль, занятие и груз; кольцо отмечает выбор. F включает/выключает следование, ручное движение камеры прекращает его. Esc или кнопка снимает выбор. Ввод адреса блокирует WASD, клики и колесо над панелями не управляют миром.

Выбор не назначает задачу и не захватывает управление племенем. Строительство, зоны и выбор зданий/ресурсов пока не входят в этот шаг. Проверки ввода: `godot_console --headless --path godot --script tests/game/test_observer_controls.gd`; реальная сцена observer проверяется также в `py -B scripts/godot/test_m2_network_integration.py` на собственном fixture-сервере.

### Управление в визуальной лаборатории

| Клавиша | Назначение |
|---|---|
| `1` .. `6` | Переключение анимаций: Idle (1), Walk In-Place (2), Walk Move (3), Carry Idle (4), Carry Walk (5), Work/Gather (6) |
| `Q`, `W`, `E` | Скорость воспроизведения: `0.25x` (замедленный шаг для проверки стоп), `1.0x` (норма), `5.0x` (ускорение) |
| `A`, `S`, `D`, `F`, `G` | Ракурсы камеры относительно персонажа: Front (A), Right Profile (S), Back (D), Left Profile (F), Game View 58° (G) |
| `Space` | Пауза / возобновление для детального осмотра контакта стопы с грунтом |
| `T` | Негативный тест: искусственный рассинхрон скорости (2.2x), проверка индикации `[FAIL]` |
| `N` | Переключение День / Ночь (солнечный свет vs динамическое пламя и тлеющие угли костра) |

### Headless-проверка проекта

```powershell
godot_console --headless --path godot --quit
```

## 5. Пайплайн 3D-ассетов

1. Исходные 3D-модели создаются и редактируются в Blender (`art/blender/`).
2. Экспорт выполняется в формат `.glb` (glTF 2.0 Binary) в папку `godot/assets/models/`.
3. Все скелетные анимации запекаются в glTF-клипы с сохранением корневой точки контакта стоп с землёй.
