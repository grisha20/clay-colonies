## Подтверждённые проблемы

### 1. Автоматическая тревога теряет возможность сняться после загрузки — P2, исправить первой

`server/src/sim/settlementAI.ts:65,88–89`. Владение тревогой хранится в `WeakMap<ColonyRuntime, boolean>`, а `colony.alarm` сохраняется. После `worldFromSnapshot` runtime другой, записи в WeakMap нет. Когда враг исчезает, Праматерь видит включённую тревогу, но не считает её своей. Ручная тревога должна сохраняться, поэтому просто выключать любую тревогу тоже нельзя.

Воспроизведение: Праматерь подняла тревогу → сериализация/загрузка → врагов больше нет → очередное обновление ИИ. Результат: `raised=true, beforeReloadClears=true, afterReloadAlarm=true, autoManage=true, threats=0`. Без загрузки та же тревога снимается. Это может держать рабочих у костра, пока игрок не снимет тревогу вручную.

Исправление: хранить происхождение тревоги в сохраняемом состоянии либо явно восстанавливать его; добавить проверку save/load для автоматической и ручной тревог.

### 2. Стройка на холмах выбирает другую точку — P2

`godot/scripts/game/world_observer.gd:522–531`. `ground_point_at` пересекает луч с плоскостью Y=0. Мир и предпросмотр уже подняты по `SurfaceTerrain.height_at`. При клике на видимую вершину холма выбирается точка за ней/перед ней, и туда отправляется команда стройки/зоны/поста.

В production-сцене холм высотой 5: точка `(120,236)` проецируется камерой и передаётся обратно `ground_point_at`; результат `(120,231.7042)`, ошибка **4.2958 мировых единицы** (больше двух клеток ограды). Существующий integration строит клики через `Vector3(x,0,z)`, поэтому не ловит расхождение с видимым рельефом.

Исправление: пересечение луча с реальной высотой поверхности/геометрией; проверить положения на склоне через проекцию поднятой точки.

### 3. «Обжиг на паузе» не останавливает текущий обжиг — P2

`server/src/sim/kiln.ts:35–61`, подпись кнопки `godot/scripts/game/priority_panel.gd:247`. Проверка `firingPaused` находится после ветки активной печи. Уже позванный житель продолжает идти к ней, дрова могут списаться, прогресс доходит до конца. Пауза блокирует только следующий вызов, хотя UI сообщает о паузе самого обжига.

Воспроизведение: активная печь, прогресс 1 → `firingPaused=true` → обновления. Итог `paused=true, fired=true, firedTotal=1`. Текущий `check:kiln` проверяет паузу до назначения, но не во время активного обжига.

Исправление: определить и реализовать семантику кнопки. Если текущая партия должна догорать, назвать её «Не начинать следующий обжиг»; если это пауза — остановить движение/списание/прогресс с сохранением задания.

### 4. Старые сохранения получают невыполнимую задачу источника — P2

`server/src/sim/objectives.ts:24,29–30,82–83`. Источники намеренно не добавляются при загрузке старого мира, но `restoreObjectives` всегда добавляет свежую цель `spring-1`. В таком мире взять источник нельзя. Это не блокирует другие пути победы, но список задач навсегда содержит невыполнимый пункт.

Воспроизведение: snapshot без `surface.springs` и `terrain.springs` → загрузка → `springs=0`, цель «Занять источник особой глины», target1/progress0/donefalse. В частности, сохранения до этапа территорий требуют этого случая миграции.

Исправление: формировать цели по возможностям карты либо отдельно мигрировать источники с явной политикой сохранности старой партии.
