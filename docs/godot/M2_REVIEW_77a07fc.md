## Что блокирует приёмку

### [P1] Безопасного отображения пути вокруг препятствий нет

`NetworkResident._process` по-прежнему безусловно делает `prev_pos.lerp(target_pos, ...)`. Никакой геометрии зданий/ограды/берега он не получает; перенесённый `SurfaceTerrain` используется только миром, не проверкой движения.

Воспроизведение: готовая хижина с `pos=(100,100)`, её shared-footprint — центр (100,100.5), радиусы (4,2.3). Snapshot endpoints (95,100.5) и (105,100.5) оба снаружи. Эталон `crossesBuilding=true`. После 50 мс интерполяции житель стоит в (100,0,100.5), ровно внутри здания. Это диагностический chord между безопасными endpoints, а не доказательство, что сервер сам выбирает такой путь; проблема возникает при пропущенных промежуточных поворотах/ускорении и обязана обрабатываться клиентом. Нового локального AI не требуется.

### [P1] Джиттер, сброс истории и конец партии не обработаны

Registry сглаживает предыдущий интервал, но временного буфера snapshots всё ещё нет. При 100-мс lerp и задержке следующего пакета до 160 мс независимый probe получает 3 неподвижных кадра из 10, переходя в idle. Положительный тест проверяет только один ровный интервал, обходя registry. Утверждение о плавности при любом ускорении/доставке шире проверки.

`last_snapshot_tick` только записывается. При tick 102→0 с прежним ID продолжается lerp того же актёра к новой цели, старое положение/история не сбрасываются. Session `status` не читается: при `defeat`, speed=1 probe сдвинул корень на 3 м за 50 мс, `is_sim_paused=false`. В реальном завершившемся мире цели могут стоять, но клиент всё равно должен отменить старое перемещение и рабочие/шаговые циклы.

Ограничение анимации 8× теперь честно описано, но это компромисс на высокой скорости, не доказанная синхронизация подошв на 20×/50×. Лабораторную калибровку не переносить на этот режим без измерения.

### [P1] «Строгий» decoder ещё пропускает значения, ломающие представление

Production `decode_and_validate_packet` принимает `protocolVersion=21.9` из-за `int(pv)`, `surface=[]`, `session=[]` и координату `x=1e309`, превращающуюся в бесконечность. Обязательные типы surface/session не проверяются, конечность числа не проверяется. После такого приёма controller/registry обращаются к session как Dictionary, возможен runtime error; бесконечная позиция нарушает transform. Отдельно проверять полный контракт используемых полей до изменения мира, без превращения ошибочного пакета в пустой snapshot.

### [P1] Ветвь переноски интеграционного теста аварийная

В `tests/integration/test_qa_network_client.gd:153` читается **несуществующее** свойство `res.cargo_mesh_instance`; в NetworkResident оно называется `cargo_prop`. Обычный integration прошёл потому, что ветка `carrying > 0` не была задействована на проверяемом snapshot. Для детерминированной проверки создан отдельный настоящий QA-fixture с `session.speed=0` и грузом у жителей **обоих** списков: top-level ants и colonies[].ants (runtime восстанавливается из второго).

```text
PASS: Received 12 live snapshots from QA server!
SCRIPT ERROR: Invalid access to property or key 'cargo_mesh_instance' ...
at test_qa_network_client.gd:153
AUDIT_GODOT_CARGO_TIMEOUT_8_SECONDS
```

Godot не завершил тест; внешний аудит прервал только свой процесс через 8 секунд, затем штатно остановил свой QA-сервер. State-dir `tmp/qa/cargo-audit-34304aa1`. Штатный Python integration использует `subprocess.run` без timeout, поэтому такой случай способен зависнуть. Ещё одна слабая проверка: heading_verified печатается как PASS даже при 0, сравнивается с current_heading, а не реальным перемещением; test_root не добавлен в дерево, AnimationPlayer автоматически не исполняется. Требуется настоящий проверяемый production pipeline, не только ручные вызовы _process.

## Оставшаяся полнота базового мира и QA

- Один fish в `surface.fish` → 0 маркеров: цикл рыб отсутствует. Carrion/deposits также не отображаются. Для M2 достаточно простых маркеров, не полного арта M4.
- `entrances=[]` после одного входа оставляет один старый костёр. Для зданий/ресурсов удаления реализованы, для костров — нет.
- Wall BoxMesh высотой 1,2 м ставится центром на Y=0: низ −0,6 м. Placeholder геометрия/ориентация/размер не соответствуют footprint; gateAxis/gateSpan/stage не используются. При той же проблеме у storage/workshop часть объёма под грунтом. Требуется опора простых форм и честные footprints, не художественная переделка.
- Полигональные координаты перенесены верно, но membership на границе не полностью совпадает: точка (284,140) — Godot true, shared TypeScript false. Тест не сравнивает автоматически общие fixtures; он проверяет несколько вручную выбранных точек.
- В успешном случае graceful-save подтверждён. Но save-error в index.ts ловится и всё равно завершается 0; fallback hard-kill после timeout раннер также превращает в 0 при stop_requested. Ошибка сохранения/аварийная очистка не должны выглядеть штатной сдачей. Сохранить happy-path и добавить отрицательные сценарии, не переписывая систему хранения.
- `--test-recording` посылает setSpeed через любой переданный URL. Ограничить изменяющие мир сценарии доказанным отдельным QA-контекстом; обычное наблюдение остаётся пассивным.
