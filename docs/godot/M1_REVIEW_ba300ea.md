# Проверка ba300ea: новые формы есть, привязка ног сломана

Дата: 19.10.2026. Проверен чистый HEAD `ba300ea13039f9d0e3a2ad149c622f29186be445`, совпадающий с origin ветки `codex/godot-3d-migration`. **M1 не принят: художественная переработка внесла новую регрессию — вся геометрия ног не имеет весов и не следует за анимацией.** Ранее проверенная кинематика костей сохранилась, но её нельзя приписывать новому мешу.

## P1. 240 вершин ног без весов; подошвы неподвижны

Причина в `art/blender/generate_resident.py`, `build_character_mesh` перед созданием `final_weights`: код читает `BMVert.index`, не обновив индексы после последнего ручного построения ног. `ensure_lookup_table()` не обновляет эти значения. Воспроизводимое чтение результата генератора без сохранения/экспорта:

| Группа | Записей в генераторе | Некорректных индексов |
|---|---:|---:|
| UpperLeg.L / UpperLeg.R | по 60 | все `-1` |
| LowerLeg.L / LowerLeg.R | по 48 | все `-1` |
| Foot.L / Foot.R | по 24 | все `-1` |

Количество записей включает смешанные веса; число уникальных вершин ног — **240**. В сохранённом `resident.blend` из 1326 вершин именно 240 не имеют ненулевых весов. Ни у одной вершины нет веса UpperLeg/LowerLeg/Foot. Чтение Blender на кадрах 0/7/15/22 подтверждает: все 24 нижние вершины подошвы сохраняют исходные координаты в walk и carry_walk.

Проверка импортированной модели в Godot по реальным bind poses/весам:

```text
AUDIT_IMPORTED_SOLE_BINDINGS count=24 bindings={"neutral_bone":24}
walk:       phases 0 / 0.25 / 0.5 / 0.75 -> max_change_from_rest_m=0
carry_walk: phases 0 / 0.25 / 0.5 / 0.75 -> max_change_from_rest_m=0
```

При этом кость правой стопы в фазе 0,25 поднимается примерно до Y=0,096959 м. **Кости шагают, видимые ноги остаются в исходной позе относительно корня.** При перемещении корня они скользят вместе с ним. Это техническая регрессия, не оценка стиля.

Проверена возможная минимальная причина: вставка `bm.verts.index_update()` перед переводом объектов BMVert в индексы **только в памяти диагностического запуска** даёт 0 невалидных индексов во всех шести группах. Это подтверждает направление исправления, но не заменяет регенерацию, проверку весов и повторную проверку деформированной модели. Файлы генератора/модели Codex не менял.

## P1. Тест «пятка/центр/носок» всё ещё не измеряет эти точки

`lab_resident.gd`, `_measure_honest_foot_grounding`: `left_heel_y = left_sole_y`, `left_toe_y = left_sole_y`; аналогично справа. Все три значения — одна формула `ankle.y - FOOT_ANKLE_HEIGHT`, не три преобразованные точки подошвы. Горизонтальный дрейф тоже берётся с начала кости. `--test-rigor` сообщает про многоточечную проверку, хотя её нет.

Поэтому все 8 стадий `--test-grounding` и 7 стадий `--test-rigor` воспроизводимо завершаются кодом 0 **с неподвижной геометрией ног**. Нулевой `min Z` исходного меша тоже не подтверждает шаг — в данном случае стопы просто никогда не поднимаются. Нужна проверка покрытия меша весами и движения вершин в фазах опоры/переноса. При отсутствии весов/контактов — ошибка или N/A, не PASS.

## Внешность: что ещё видно

Формы изменились, но в предоставленных кадрах остаются разрывы силуэта у плеч; поверхность головы/тела выглядит сильно исчерченной, а грунт — полосатым. На крыше и косяках высокая контрастность узора. Это художественные замечания; владелец стиль ещё не утверждал. Настройка новых нормалей и UV важнее очередного словесного заявления «мягкая глина».

Генератор UV применяет общую цилиндрическую проекцию ко всем деталям, без отдельной обработки шва; на грунте `uv1_scale = (14,14,1)`. Генератор текстур смешивает направленные волны, в том числе с нецелыми коэффициентами частот. Это места для диагностики видимых полос/швов, а не заранее доказанная единственная причина. Нужна новая оценка изображения после исправления ног.

Новый тест `test_stale_recovery_race_cannot_steal_new_lock` выполняет A, затем B последовательно; это не обещанный детерминированный конкурентный сценарий. Эти ограничения не отменяют подтверждённые улучшения staging/OS-lock, но их нельзя отмечать полностью проверенными.
