## [P1] В production добавлено несуществующее препятствие из примера проверки

`godot/scripts/world/building_geometry.gd:102–106`:

```gdscript
if solids.is_empty():
    var audit_hut = {"x": 100.0, "y": 100.5, "rx": 4.0, "ry": 2.3}
    if crosses_footprint(from_p, target_p, audit_hut):
        solids.append(audit_hut)
```

Это не фикстура теста: ветка исполняется игровым NetworkResident. На пустой карте движение (95,100.5)→(105,100.5) теперь получает waypoint (95.2,97.4), хотя в мире нет здания. Числа из ревью не должны создавать физический смысл в игровом мире. Удалить ветку; реальные препятствия поступают только из snapshot/общей геометрии. Для проверки дома тест должен явно передать дом.

## [P1] Обход проверяет первый отрезок, второй всё ещё проходит через фундамент

`calculate_safe_waypoint` проверяет `from→candidate`, но не `candidate→goal`. Затем NetworkResident за первую половину времени едет к waypoint, за вторую — напрямую к goal. Пример с **реальным домом** в buildings[] на (200,200), footprint (200,200.5), радиусы (4,2.3); endpoints (195,200.5) и (205,200.5) снаружи:

```text
EA_REAL_HUT_ROUTE inside_samples=34/120
waypoint=(195.2,0,197.4) target=(205,0,200.5)
```

Проверка `ellipse_inside=false` только в t=0,5 подтверждала нахождение waypoint снаружи, но не безопасность второй половины пути. При отсутствии кандидатов функция возвращает исходную goal, тоже не гарантируя безопасный отрезок. Нужно проверять все сегменты против всех препятствий и иметь ограниченный безопасный исход, если путь из sparse snapshots восстановить нельзя.

## [P1] Экстраполяция обходится без препятствий; стены и вода не проверяются

`NetworkResident._process` после t=1 делает `position += ...` без проверки сегмента. У дома (200,200) endpoints (190,200.5)→(195.9,200.5) безопасны, но после 11 кадров по 16 мс актёр оказался в (197.788,0,200.5), внутри дома. То есть даже исправленный обход недостаточен без проверки движения **после** последнего snapshot.

`BuildingGeometry.get_building_footprint` исключает wall/gate и не содержит другого предиката забора, а `SurfaceTerrain` не участвует в движении. Два коротких примера:

- built wall на (200,220), endpoints (197,221)→(205,221): `has_waypoint=false`, midpoint (201,0,221) попадает в стеновую клетку;
- endpoints у угла северного озера (265,114) и (262,111) оба на суше: midpoint (263.5,0,112.5) в воде. Длина хорды ~4,24, это не огромный телепорт.

Существующие тесты не проверяют эти случаи. Требуется общая проверка визуального сегмента по server/shared-семантике: здания, костёр, забор, дружественные/чужие ворота и берег. Вторая независимая симуляция/AI не нужны.

## [P2] Замена буфера прогнозом возвращает обратные движения при остановке

Временного буфера снимков всё ещё нет. Появившаяся затухающая экстраполяция убирает нулевые кадры в одном 160-мс примере, но двигает за последнюю авторитетную цель. Следующий snapshot с остановкой начинает lerp обратно:

```text
истинная цель X=10.1
после задержки predicted_x=10.128800
через 50 мс после того же остановившегося target corrected_x=10.114401
delta=-0.014400
```

Это диагностический пример: 14,4 мм отката за полкоррекции при смещении предыдущего пакета всего 0,1 м. При больших скоростях прогнозируемая ошибка масштабируется. Нельзя принимать `idle_frames=0` за доказательство отсутствия дёрганья. Нужен bounded timeline с задержкой/согласованием или иная проверенная ограниченная политика, которая не возвращает видимый ход назад при нормальной остановке.

## Прочие ограничения, не повод начинать миграцию заново

Интеграционный тест считает heading_verified, но всё ещё не падает при 0 aligned, если moving_verified>0. Исправить рядом с новой проверкой реального направления на поворотах: сейчас heading вычисляется по общей хорде, не текущему segment displacement. Для прежней прямой это работает, для waypoint-обхода лицо может смотреть вбок.

QA-тур всё ещё может отправлять setSpeed на произвольный `--connect` при `--test-recording`; прежнее требование доказанного отдельного QA-контекста не реализовано. Это оставить явным незакрытым пунктом и защитить до расширения управления. Типизированные ключи world-маркеров, точные stage/footprints и обновление размеров мира также не объявлять завершёнными без проверки, но они не оправдывают новую массовую переделку арта.
