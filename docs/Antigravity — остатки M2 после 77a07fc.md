## 1. Сначала починить доказательства

Файлы: `godot/tests/integration/test_qa_network_client.gd`, `scripts/godot/test_m2_network_integration.py`, fixtures.

- Ветвь carry сейчас читает несуществующий `cargo_mesh_instance` и зависает. Использовать настоящее `cargo_prop`, проверять видимость/сокет и срабатывание ветви. Гарантированный fixture с грузом обязан записывать runtime ants в colonies[].ants, не только верхний ants. Подтвердить, что проверен хотя бы один носильщик каждого племени.
- Добавить test_root в реальное дерево и дать production AnimationPlayer/обработке кадра исполняться, без двойного _process. Отсутствие ScriptError и завершение теста с ограниченным timeout обязательны. Python оборачивает каждый Godot-процесс timeout и убирает только своё дерево при сбое.
- Heading сравнивать с фактическим перемещением, проверять ненулевое число движущихся образцов и точные server ID/позиции, а не печатать PASS при любом heading_verified. Преднамеренная ошибка должна завершать тест ненулевым кодом.
- Все последующие проверки проходят через production decoder→controller/registry/world_view, не копии формул в тесте. Пустой грузовой fixture или пропуск ветки не считается проверкой переноски.

## 3. Безопасная временная траектория и завершение партии

`entity_registry.gd`, `network_resident.gd`, при необходимости небольшие модули timeline/geometry и fixtures из shared.

- Сделать ограниченный временной буфер/задержку отображения по основному ТЗ. Сглаживание предыдущего dt не заменяет буфер: при следующем пакете через 160 мс прежний 100-ms lerp завершается и 3 кадра стоит. Проверить последовательность реального времени 100/160/40 мс, короткую пачку пакетов, короткий stall, 1/5/20/50×. Не делить broadcast interval на скорость симуляции.
- Не проводить прямую интерполяцию через препятствие. Воспроизведение в аудите: hut=(100,100), safe endpoints=(95,100.5) и (105,100.5), midpoint попадает в центр фундамента. Аналогично проверять забор/дружественные и чужие ворота/берег/костёр по TypeScript-эталону и общим JSON-fixtures. Не добавлять локальную вторую симуляцию/AI; если пакетов недостаточно для восстановления безопасного поворота, использовать ограниченное документированное восстановление, которое не рисует сквозной проход и не блокирует актёра бесконечно.
- Уменьшение tick/смена мира/захват/спасение/телепорт сбрасывают старую историю. `session.status != playing` фиксирует перемещение/шаг/работу даже при speed=1. Добавить regression на старый ID при tick 102→0 и на pending lerp при defeat/victory.
- Сохранить уже исправленные направление и freeze-позу. Честно показать компромисс частоты шага на 20×/50×; не обещать лабораторную опору при клипе, ограниченном 8×. На обычном 1× и 5× проверить фактическое скольжение в живом клиенте, не только значения speed_scale.

## 5. Сохранить успешный graceful-save, честно обрабатывать ошибки

`server/src/index.ts`, `qa_server.py`, targeted tests. Успешный save/restart уже подтверждён. Не перестраивать его заново.

- Ошибка записи snapshot возвращает ненулевой результат; fallback hard-kill после timeout не превращается в «штатный 0». Проверить оба отрицательных случая и освобождение своих порта/lock. Если loop продолжает меняться во время save, завершать его согласованно, не возвращая успех до подтверждения записи.
- Не вводить общедоступную сетевую остановку сервера. Сохранить env-ограниченный QA stop-file. Мутирующие команды тура (`setSpeed`) разрешены только на доказанном собственном QA-сервере, не на произвольном --connect. Обычный наблюдатель пассивен.
- При занятом порте тест отказывает, а не подключается к чужому серверу. QA-state уникальный, явно заданный, все четыре state-файла изолированы; корневые snapshot/genome не использовать.
