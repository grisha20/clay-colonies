# Шаг и крупные месторождения

## План по файлам

1. `motion.ts`, `motionCheck.ts`, `motionPreview.ts`: связать шаг с реальной дистанцией, поднять слишком низкий предел частоты при 1×, отдельно ограничивать ускоренное время. Витрина должна проверять реальную скорость рабочих (~10.5 клеток/с), а не только прежние 6.
2. `shared/types.ts`, новый `shared/resourceDeposits.ts`, `world.ts`: большие конечные месторождения глины/камня, несколько узлов рабочих мест, равная обеспеченность обоих племён. Снапшот v21, миграция старой партии без сброса; истощённые месторождения не восстанавливаются загрузкой.
3. `economy.ts`: распределять рабочих по местам, сохранив обычные приоритеты и необходимость кирок для камня. Новые площадки — открытые карьеры с проходимым рабочим дном; новая сложная система подземных шахт не требуется.
4. Отрисовка, подсказки, миникарта, правила размещения построек: крупные узнаваемые места добычи, видимый остаток запаса, защита от застройки рабочей площадки.
5. Проверить шаг на видео/в движении при ¼× и 1×, добычу и доставку обоих материалов, оба племени, загрузку и истощение, типы/сборку/`check:slice`; commit и push.

## Риски

- Более частый шаг не должен раскачивать корпус или становиться нечитаемым при 50×.
- Нельзя вернуть старые зависания: отдельные рабочие места не должны концентрировать всех в одной точке.
- Запас должен переживать сохранение, а старые здания и назначения оставаться на месте.
- Карьеры должны выглядеть частью грунта, а не новой парящей картинкой. Для растровых площадок применяется imagegen, исходные изображения хранятся в проекте.

## Результат

- Обычный шаг теперь проходит полный цикл примерно за 3 клетки пути (24 экранных пикселя при cell=8), с учётом уменьшенного дождём размера тела. Прежний предел 10 рад/с обрезал цикл уже при обычной скорости рабочего ~10.5 клетки/с, из-за чего тело уезжало заметно дальше, чем отрабатывали ноги. При 1× потолок поднят до 32 рад/с, на ускорении отдельно ограничен 18 рад/с. Скорость самой симуляции не увеличена. Корпус сохраняет опору на подошвы.
- Восемь конечных месторождений: четыре глиняных по 4800 и четыре каменных по 7200. В новой партии у обоих племён одинаковый близкий доступ к обоим материалам; центральные и дальние площадки дают повод выходить из лагеря.
- У каждого месторождения шесть разнесённых рабочих мест. Рабочий подходит вплотную к своему месту (радиус работы 0.35 клетки), добывает обычными ударами и носит материал на склад. Кирка для камня обязательна. Назначения учитывают занятые места у обоих племён; исходные мелкие ресурсы сохранены.
- Карьеры — открытые выработки на поверхности, с проходимым рабочим дном и низким задним краем. Подземная шахта и отдельная постройка шахты в этот этап не входят. PNG с прозрачностью созданы через imagegen, оригиналы и точные запросы сохранены в `client/public/assets/environment/deposits/`.
- Площадка рисуется в слое земли под жителями и следами. Вокруг появляется мягкая неровная расчистка, соединяющая карьер с травой и общим грунтом. Остаток запаса показывается при наведении; на миникарте видны отдельные отметки. Истощённый карьер остаётся с приглушённым цветом и пометкой «Истощён».
- Здания, заборы и ворота нельзя ставить на рабочую площадку. Обычное перемещение через открытое дно разрешено.
- Снапшот/протокол v21: старой партии добавляются карьеры без сброса жителей, зданий, добываемых старых узлов и назначений. Уже созданные позиции сохраняются, запас не пополняется перезагрузкой. Текущая работающая партия проверена через снимок сервера: месторождения присутствуют, рабочие уже назначены на их узлы.

## Проверки

- `npm run check` и `npm run build -w client` — успешно.
- `npm run check:motion` — 29 сценариев, включая соответствие шага дистанции при 2.2/6/10.5/13 клетках/с и 30/60 FPS, паузу и ограничение на ускорении.
- `npm run check:deposits` — 8 сценариев: расположение, миграция v20, конечность запаса, сохранение, запрет застройки, отдельные места/добыча/доставка обоих материалов обоими племенами, кирки и сохранение количества материала.
- `npm run check:slice` — все проверки среза успешно.
- `npm run check:gameplay` — 39 сценариев успешно, включая 20 игровых минут и восстановление повреждённого сейва.
- `npm run check:world` — 11 сценариев успешно, включая 40 игровых минут самостоятельного развития Б.
- `npm run check:fences` и `npm run check:navigation` — по 13 сценариев успешно.
- В браузере проверены настоящая карта действующей партии (только камера), рабочие места в витрине, обычная ходьба и медленная ходьба правителей. Сохранение пользователя не сбрасывалось, команды изменения партии не отправлялись. Витрина держит около 58–59 FPS, подготовка кадров с карьерами около 0.3–1.1 мс на текущем ПК.
