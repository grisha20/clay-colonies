# Игровой срез и идеи со скриншота — 17.10.2026

## План до изменений

Цель: предсказуемое управление поселением, подготовка к опасности, защита и итог партии. Дополнительно — первый рабочий вариант идей Степана со скриншота.

- Озёра, рыбы и рыбалка уже реализованы: сохраняем существующие контуры и механику.
- `shared/types.ts`, новый `shared/dayCycle.ts`: версия 15, состояние партии, набега, озёр, захвата, водяных атак. Старые v13/v14 загружаются с безопасными значениями по умолчанию.
- `server/src/sim/economy.ts`: уменьшение назначений освобождает лишних работников после сдачи груза; интерфейс объясняет ограничения.
- Новые `sim/session.ts`, `sim/wildlife.ts`, `sim/ant/defense.ts`: тревога, пост обороны, обучение водомётов в мастерской, пополнение на сухом берегу, похитители озёр, ночные жуки, спасение пленника, набеги и итог.
- `sim/step.ts`, `enemy.ts`, `world.ts`, `ant/step.ts`: подключение механик, размокание с глиняным следом, рост населения по решению игрока, сброс временных кэшей.
- `net/socket.ts`, `index.ts`: проверенные команды, создание еды только в явно включённой песочнице.
- Клиент: отдельная панель защиты, безопасный инструмент выбора, состояние суток/набега, отображение новых существ, водяных струй и размокания; движущиеся солнечные тени, ночное освещение.
- Сценарные проверки нового поведения и существующий `check:slice`; обновление README.

## Риски и ограничения

- Захваченный житель не должен одновременно работать, есть или телепортироваться через стены. Связь хранится в снапшоте; гибель похитителя освобождает пленника.
- Озёрный монстр может двигаться в воде; обычные жители и жуки используют сухие маршруты. Водомёт набирает воду с берега, не входя в озеро.
- Рост озёрной угрозы ограничен: жертвы повышают число монстров до верхней границы, а не создают бесконечный спавн.
- Вода уменьшает тело и оставляет добываемую глину; высыхание не возвращает уже потерянную массу. На смерть остаток глины выдаётся один раз.
- Новые состояния должны переживать загрузку; сохранение пишется через временный файл и переименование. Существующее сохранение не удаляется.
- Это начальный баланс, требующий живой партии. Огороды, кооператив, полная система прокачки/оружия и воспроизводимый seed остаются отдельными следующими этапами.

## Результаты проверки (18.10.2026)

- `npm run check` — PASS, сервер и клиент.
- `npm run check:gameplay` — PASS, 24 сценария. Есть совместный прогон 12000 тиков (20 игровых минут), захват/спасение, рост озёрной угрозы, вода, стрельба по другому племени, корректное засчитывание убийства паука, ритуал, поражение и восстановление сейва.
- `npm run check:slice` — PASS. Исправлена прежняя неточная проверка стены: порог перед стеной считал развороты пересечениями. Теперь проверяется весь отрезок перемещения через реально занятые клетки и требуется ровно ноль пересечений.
- `npm run build -w client` — PASS. Добавлена команда сборки и `target: es2022`, согласованный с уже существующим top-level await и TypeScript target.
- WebSocket-интеграция — PASS: новая партия сбрасывает итог и скорость, песочница готовит тестового водомёта, тревога включается/отменяется, пауза приходит в снапшот.
- Браузер: проверены дневной/ночной вид, панель защиты, переключатели тревоги/роста, причины ожидания работ, отсутствие ошибок в консоли. Исправлены наложение строк приоритетов и артефакт ночной маски от второго лагеря за экраном.
- Поведенческие проверки рыбалки расширены исправлением: `assignForageRoles` больше не сбрасывает профессию рыбака каждый тик.
- Проверки использовали временные сохранения и геномы; основной `snapshot.json` не удалялся.

Это функциональная приёмка первого варианта, не окончательная настройка сложности. Нужна обычная партия на 30–45 минут с оценкой скучных пауз, потерь у озёр, удобства тревоги и стоимости пополнения водомётов.

## Следующие отдельные шаги

Приоритет конкретной стройки/ремонта, очередь заказов мастерской, воспроизводимый seed, полноценный вводный сценарий, огороды и кооператив. Первый водомёт для проверки доступен в явной песочнице; в матче обучение требует мастерскую и ресурсы.
