# План случайного мира — 21.10.2026

Решения владельца (21.10.2026):

- Нужен рельеф: холмы и горы, больше леса, карта не должна казаться пустой. В будущем — животные в лесу и на полях.
- Племена расселить по разным углам большой карты.
- Озёра не обязаны быть «ступенчатыми» — это наследие 2D-текстур. Нужна **случайная генерация мира**.
- **Холмы проходимы, горы — нет** (непроходимы, как вода).
- При запуске — **меню: продолжить / новая игра / загрузить сохранение**.
- Порядок работ оставлен исполнителю: сначала мир (A→B→C), затем жители за работой, HUD, погода и ночь.

## Как было до работ

Местность — константы общего кода: два озера `north`/`south` в `shared/surfaceTerrain.ts`, лагеря `CONFIG.surfaceEntrance`/`surfaceEntranceB` (120/240 и 360/240), места карьеров в `shared/resourceDeposits.ts`. `LakeId = "north" | "south"` используется в рыбалке, озёрных монстрах, навигации по воде, защите и сессии (`session.lakes`). Godot повторяет контуры в `godot/scripts/world/surface_terrain.gd`. 2D-клиент рисует воду через общие `isWaterAt`/`lakeFieldAt`, поэтому произвольные озёра покажет без переделки текстур.

## Этап A — местность как часть мира

| Файл | Изменение |
|---|---|
| `shared/types.ts` | `Surface.terrain?: SurfaceTerrainData` (seed, lakes[], hills[], mountains[]); `LakeId` → `string`; протокол v22 |
| `shared/surfaceTerrain.ts` | «текущая местность» (`setSurfaceTerrain`), прежние функции работают поверх неё; `LEGACY_TERRAIN` = нынешняя карта; горы в предикатах непроходимости; высота `heightAt` из холмов |
| `shared/lakeNavigation.ts`, `lakeHabitat.ts`, `amphibianNavigation.ts` | кэши сбрасываются при смене местности |
| `server/src/sim/fishing.ts`, `wildlife.ts`, `ant/defense.ts`, `session.ts` | перебирать озёра мира вместо двух констант; `session.lakes` — по id |
| `shared/surfaceNavigation.ts`, `surfaceAccess.ts`, `buildingPlacement.ts` | горы блокируют путь и стройку так же, как вода |
| `server/src/sim/world.ts` | `worldFromSnapshot`: сохранение без `terrain` получает `LEGACY_TERRAIN` — старая партия продолжается на старой карте |
| `client/src/main.ts` | установка местности из снимка |
| `godot/scripts/world/*` | местность из снимка вместо констант; вода, берега, декор, навигация по данным |

Риск: тонкие различия навигации TS ↔ GDScript для гор. Проверка: bench-проверки сервера, тесты навигации Godot, общий набор точек «вода/гора/суша» из одного fixture для обеих реализаций.

## Этап B — генератор и стартовое меню

- `server/src/sim/terrainGen.ts`: по seed — лагеря в противоположных углах (≈90/90 и 390/390, пара углов случайная), 2–4 озера естественной формы, 2–3 горных массива, холмы, лесные массивы и рощи, карьеры и стартовые ресурсы симметрично у обоих лагерей.
- Проверки генератора: лагеря связаны проходимым путём, у каждого племени сопоставимые ресурсы в радиусе, вода/горы не перекрывают лагеря и карьеры, 50 случайных seed без отказов.
- Баланс: дорога между племенами длиннее — пересмотреть время набегов, цели партии, радиусы поиска еды; партия по-прежнему 2–3 часа.
- Сохранения: каталог слотов, команды `listSaves` / `loadSave` / `newGame { seed? }`; автосохранение текущей партии сохраняется как «Продолжить».
- Godot: стартовое меню «Продолжить / Новая игра / Загрузить»; 2D-клиент — существующий `newGame` продолжает работать.

## Этап C — рельеф и лес в Godot
