# Долгая партия, озёра и соперник

## План и риски

1. `ant/movement.ts`, `building.ts`, общий геометрический модуль: исправить маршруты у воды, не отправлять жителя на недостижимую точку, проверить все способы перемещения. `main.ts`: сглаживание не должно срезать здания/озёра между пакетами, особенно на ускорении. Риск — застревание вместо прохода: регрессии с реальными маршрутами и измерение прогресса.
2. `session.ts`, `objectives.ts`, `config.ts`, UI: первые пауки и дождь — этапы развития. Победа доступна после двух игровых часов; финальный предел — три часа, поражение при гибели племени остаётся. Честно показывать время финала. Сохранение v16 мигрировать без сброса мира; ранее завершённую партию автоматически не перезапускать.
3. `wildlife.ts`, `world.ts`: обитатель озера присутствует с начала, плавает по воде, иногда выбирает прибрежную прогулку, замечает людей и преследует, ест рыбу. Убрать периодическое появление на берегу; дополнительное потомство появляется в глубине после роста угрозы. Риск — выход из озера через узкие перешейки: проверка всего отрезка движения.
4. `fishing.ts`, `main.ts`, рендер рыб: плавный поворот каждый тик, стабильная анимация плавников без скачков разных изображений, непрерывность показа при изменении состояния.
5. Новый `settlementAI.ts`: племя Б добывает, строит мастерскую/жильё/оборону, обучает стражу, пополняет потери и конкурирует за ресурсы без бесплатных материалов и мгновенных зданий. Явное ручное управление выбранным племенем отключает его автопилот; племя А по умолчанию ручное. Риск — тупик экономики: проверка длительной симуляцией.
6. Земля: новые глиняные материалы и небольшие декоративные травы/цветы у основания готовых зданий, утоптанный вход без растительности. Сохранить изображения красивых зданий. Генерируемые PNG сохранить в проекте с запросами, проверить масштаб и повторяемость.

Проверки: типы, игровые сценарии, срез, движения, длительная автономная стройка Б, визуальная проверка; затем коммит и push. Пользовательское сохранение не использовать для испытаний.

## Реализовано

- Общий `shared/surfaceNavigation.ts`: обход воды, костров и фундаментов; свои ворота проходимы. Сборщики еды больше не срезают маршрут вдоль старого следа. Еда и растворённая глина под водой исключены из обычных целей добычи. На клиенте интерполяция идёт по безопасным сегментам, а не через здание между пакетами.
- `shared/lakeNavigation.ts`: проверка всего отрезка и обход выступов берега используются сервером монстров и клиентом рыб/монстров. В каждом озере есть постоянный обитатель с начала партии. Он патрулирует воду и береговую кромку, преследует людей, утаскивает их, при голоде ест рыбу. Пополнение угрозы появляется в глубине вдали от жителей; после гибели есть задержка восстановления.
- Рыбы постепенно поворачивают каждый тик по кратчайшей дуге, включая разворот на 180°. Смена «плывёт/приманивается» не сбрасывает интерполяцию. Визуально тело стабильно, хвост движется отдельно; кадры с разной формой силуэта больше не прыгают.
- Матч: цели отмечаются сразу, но победа доступна после 72 000 тиков (2 часа при 1×); выживание до 108 000 тиков завершает партию. Раннее поражение при гибели всех жителей сохранено. Текущий финал старого сохранения не отменяется автоматически.
- Автопланировщик второго племени раз в десять игровых секунд меняет приоритеты, ставит обычные стройплощадки, развивает инструменты/жильё/склады/оборону, обучает водомётчиков и реагирует на угрозу тревогой. Материалы добываются и доставляются жителями. Исправлен тупик стройки, когда остаток древесины меньше 0.5 нельзя было взять со склада.
- Переключение племени A/B передаёт ручное управление выбранному племени, оставляя второе на автопилоте. Цели пересоздаются для нового выбора. Это общий выбор сервера; владение племенами несколькими игроками и организованные наступательные отряды остаются отдельными задачами.
- Мягкие глиняные материалы поверхности, плавная граница утоптанного лагеря, небольшие травы/клевер/цветы вокруг готовых зданий с открытым подходом к двери. Изображения зданий сохранены. Запросы и происхождение PNG: `client/public/assets/environment/clay-v2/PROMPT.md`.
- Маски грунта и глубины используют собственные фильтры: временная маска после запекания земли больше не оставляет в пуле Pixi ссылку на освобождённую текстуру и не останавливает следующую отрисовку.
- Снапшот/протокол v17, миграция v13–v16 без удаления мира.

## Проверка

- `npm run check`, `npm run check:slice`, `npm run check:gameplay` (38 сценариев), `npm run check:motion` (26 сценариев), `npm run check:world` (10 сценариев), `npm run build -w client`.
- Новый `check:world` изолирует свои файлы во временном каталоге. Проверяет длительность матча, миграцию, дробную доставку, реальный переход сборщика вокруг озера, интерполяцию у хижины, плавность рыб, жизнь/кормление монстров и ручной выбор племени.
- 24 000 тиков (40 игровых минут) автономной экономики с обычными расходами: Б выросло до 35 жителей, построило мастерскую, дополнительные хижины, второй склад, ворота и стены. Штормы смывали часть стен; поселение возобновляло стройку. Угрозы для этого экономического сценария отключены.
- Дополнительно отдельный сервер с новым миром, опасностями и отдельными файлами сохранения прошёл 16 008 тиков: А — 23 жителя, Б — 31, Б достроило мастерскую, жильё, склад и оборону. В браузере проверены сцена дождя, новый грунт, растительность, смена племени и камера. После исправления масок — около 58 FPS и 1 мс отрисовки на этой сцене.
- Полная живая партия на 2–3 часа пока не пройдена. Новый предел финала проверен сценариями; баланс длинной партии требует дальнейшего наблюдения.
